# Проверка безопасности сайта — 10 октября 2026

Проверяемый сайт: https://dur0vd.github.io/ska_hist/

На опубликованном сайте сделаны несколько одиночных HTTP-проверок. Нагрузочные атаки, перебор ключей, изменение учебных материалов и использование настоящего ключа преподавателя не проводились. В браузерных сценариях GitHub API был заменён имитацией, а ключ — фиктивной строкой.

## Обнаружено и исправлено

1. **Исполнение кода при обработке объявления в админке.** `stripTags()` разбирал непроверенный HTML через `innerHTML` в активном документе. В локальном браузере специально подготовленное объявление установило безвредный тестовый флаг. Это требует попадания вредной разметки в данные объявления; возможность записать её анонимно не обнаружена. Теперь HTML очищается DOMPurify, а текст извлекается в инертном документе. Объявления дополнительно очищаются при сборке, дата выводится как текст.
2. **Активные вложения.** Форма объявления принимала HTML. В имитации GitHub такой файл успешно отправлялся как вложение. Его открытие на том же origin было особенно опасно из-за постоянного ключа в localStorage. Теперь принимаются только документы, растровые картинки и ZIP; HTML/SVG/скрипты/исполняемые файлы отвергаются. Публикация также проверяет вложения. Ключ хранится только в памяти вкладки, старые значения localStorage/sessionStorage удаляются.
3. **Избыточный доступ локального предпросмотра.** По коду сервер слушал все интерфейсы и раздавал рабочую папку, в том числе возможные приватные документы. Теперь он слушает только 127.0.0.1, обслуживает публичные файлы и корректно отклоняет неверные URL. Проверки выполнены на синтетических файлах, настоящий документ с ключом не читался.

Дополнительно: добавлена CSP для скриптов/ресурсов, ограничены сетевые подключения админки, интерфейс управления не показывается внутри iframe, тесты безопасности включены в сборку.

## Проверки после исправления

- 30 браузерных случаев: 15 вариантов вредной разметки, каждый после браузерной и серверной очистки. Без CSP в тестовом стенде, чтобы политика не скрывала ошибки очистки. Исполнение тестового кода и сохранение опасных элементов не обнаружены.
- 4 запрещённых типа вложения отклонены до записи в имитацию GitHub.
- Старые сохранённые ключи удаляются; успешный вход не сохраняет новый ключ и очищает поле ввода. Обновление страницы снова требует входа.
- Редактор в iframe заблокирован. Неверный ключ не открывает рабочую область.
- Обычные операции редактора работают: таблицы, документы, сохранение, конфликт SHA, сохранность старых текстов и PDF.
- `npm test`: 3 группы проверок пройдены — очистка HTML, типы вложений, приватность/устойчивость локального предпросмотра.
- `npm audit --omit=dev`: 0 известных уязвимостей на момент проверки. Это не гарантия отсутствия неизвестных уязвимостей.
- На живом GitHub API запись без ключа и с одним заведомо неверным ключом вернула **401**. Тело запросов было пустым объектом; файлов не создано.
- На живом сайте `.git/config`, `.env` и путь к исходным JSON — **404**. Главная и админка — **200**, HTTPS принудительно включён.

## Что остаётся ограничением архитектуры

Ключ GitHub с правом Contents: write даёт право менять файлы выбранного репозитория. Статическая админка не может превратить его в серверную роль «редактировать только учебные материалы». Выдавать ключ следует только доверенному редактору и ограничивать его этим репозиторием; classic-токен с более широкими правами для этого нежелателен.

GitHub Pages не отдавал CSP и X-Frame-Options для успешных страниц. CSP добавлена в HTML; ограничение iframe в админке выполнено кодом интерфейса, а не заголовком frame-ancestors. Для полной изоляции авторизации, HttpOnly-cookie и заголовков безопасности нужен отдельный сервер/домен редактора.

Файлы сайта и публичного репозитория доступны всем. Результаты проверки не подтверждают безопасность документов Office/PDF от вредоносных макросов, не являются испытанием инфраструктуры GitHub и не оценивают устойчивость к DDoS.
